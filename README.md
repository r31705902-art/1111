# V_N — архив стримов

Первая версия: сайт-архив длинных записей (2–5 ч) со своим плеером, входом через Telegram-бота,
админ-панелью и роем из 14–50 слабых edge-нод Render (Free, 0.5 CPU / 512 MB) на разных аккаунтах.
Хранилище — Blomp (OpenStack Swift). Ноль npm-зависимостей: только Node 24 (`node:sqlite`, `fetch`, `zlib`).

```
            ┌──────────── Telegram ────────────┐
            │  vn-bot (Render 0.5CPU/512MB)    │  вход, магические ссылки, уведомления
            └───────────────┬──────────────────┘
                            │ BOT_SECRET
 браузер ──HTML/API──► vn-main (Render) ──── SQLite (+бэкап в Blomp каждые 2 мин)
    │                       │  ▲ heartbeat / команды (SWARM_SECRET)
    │  ping-проба 2–3 нод   │  │
    └──── видео-сегменты ──►  vn-edge × 14–50 (разные аккаунты Render, разные регионы)
                               │  RAM-кэш + single-flight + префетч следующих сегментов
                               ▼
                             Blomp  ◄──── vn-encoder (твой ПК / VPS / GitHub Actions) пишет HLS
```

## Что в архиве

| Папка | Что это |
|---|---|
| `main/` | главный сервер: SPA (сайт + плеер + админка), API, авторизация, координатор роя, бэкапы БД. `main/Dockerfile` |
| `edge/` | нода роя: отдаёт сегменты видео из Blomp с RAM-кэшем. Один образ на все 14–50 аккаунтов. `edge/Dockerfile` |
| `bot/` | Telegram-бот (вход, `/login`, `/me`, `/latest`, `/notify`, `/logout`). `bot/Dockerfile` |
| `encoder/` | кодировщик ffmpeg (SVT-AV1/libaom/x264) → HLS fMP4 → Blomp. `encoder/Dockerfile` |
| `shared/` | общий код: Swift-клиент Blomp, роутер, токены, edge-ядро |
| `images/` | **готовые собранные образы** (linux/amd64): `vn-main-edge-bot.tar.gz` (vn-main, vn-edge, vn-bot) и `vn-encoder.tar.gz` |
| `env/` | шаблоны переменных окружения `*.env.example` |
| `deploy/` | Render Blueprint-ы для main / edge / bot |
| `.github/workflows/` | `images.yml` — сборка и публикация образов в GHCR; `encoder.yml` — бесплатный кодировщик на GitHub Actions |
| `scripts/` | `build-images.sh/.bat` (собрать из исходников), `load-images.sh/.bat` (загрузить готовые и запушить) |
| `docker-compose.yml` | весь стек локально одной командой |

**Логины/пароли в архив не вложены** — везде заглушки. Тестовый пароль Blomp, который ты прислал,
лучше сменить после настройки.

## Готовые образы

```sh
docker load -i images/vn-main-edge-bot.tar.gz     # vn-main:latest, vn-edge:latest, vn-bot:latest
docker load -i images/vn-encoder.tar.gz           # vn-encoder:latest (ffmpeg 9 static внутри)
# или сразу загрузить и запушить в свой реестр:
docker login ghcr.io && ./scripts/load-images.sh ghcr.io/<твой_логин>
```
Render не принимает tar-файлы — ему нужен образ в реестре (GHCR/Docker Hub) **или** сборка из Git-репозитория по Dockerfile.
Самый простой путь — залить папку в GitHub-репозиторий: Render сам соберёт Dockerfile, а `images.yml` дополнительно
опубликует образы в `ghcr.io/<логин>/vn-*` (сделай пакеты public, чтобы любой аккаунт Render мог их тянуть без логина).

## Развёртывание по шагам

### 1. Секреты
Сгенерируй три длинные строки (`openssl rand -hex 32`): `SWARM_SECRET`, `BOT_SECRET`, `ENCODER_TOKEN`.
Они должны совпадать у main и у соответствующих сервисов.

### 2. Бот
1. @BotFather → `/newbot` → получи `BOT_TOKEN` и username.
2. Свой Telegram ID узнай у @userinfobot — он пойдёт в `ADMIN_TG_IDS` (первый вход сразу даёт роль админа).

### 3. Главный сервер (vn-main)
Render → New → Web Service → Docker (репозиторий, Dockerfile `main/Dockerfile`, context `.`) или «Existing image»
`ghcr.io/<логин>/vn-main:latest`. План Free. Переменные — из `env/main.env.example`:
`PUBLIC_URL`, `BLOMP_USER`, `BLOMP_PASS`, `SWARM_SECRET`, `BOT_SECRET`, `ENCODER_TOKEN`, `BOT_URL`, `BOT_USERNAME`, `ADMIN_TG_IDS`.
Health check path: `/health`. Диск на Free не сохраняется — поэтому БД каждые `BACKUP_EVERY_SEC` секунд (и при
остановке) уходит в Blomp (`sys/db/latest.gz` + ежедневные копии), а при старте автоматически восстанавливается.

### 4. Бот (vn-bot)
Отдельный сервис (свой аккаунт или тот же), `bot/Dockerfile`, переменные из `env/bot.env.example`:
`BOT_TOKEN`, `MAIN_URL`, `SITE_URL`, `BOT_SECRET`. Режим `poll` работает без вебхука.
Бот и main пингуют друг друга, поэтому оба не засыпают.

### 5. Рой edge-нод (14–50 шт.)
На **каждом** аккаунте Render: New → Blueprint → `deploy/render-edge.yaml` (или Web Service с образом
`ghcr.io/<логин>/vn-edge:latest`). Переменные: `MAIN_URL`, `SWARM_SECRET`, `EDGE_REGION` = регион сервиса
(`frankfurt`, `oregon`, `ohio`, `virginia`, `singapore`). Нода сама зарегистрируется в main (настройка
«автоодобрение» в панели) и появится во вкладке **Серверы · рой**.
Совет: для зрителей из СНГ/Азии большинство нод держи во `frankfurt`, часть — в `singapore`.
По желанию впиши в карточке ноды Render API key + service id — тогда кнопки «выкл/вкл/рестарт»
реально приостанавливают/возобновляют сервис через Render API.

### 6. Кодировщик
Кодирование 2–5-часового видео на 0.5 CPU невозможно, поэтому оно вынесено:
* **ПК/VPS:** `docker run -d --restart unless-stopped -e MAIN_URL=… -e ENCODER_TOKEN=… -v vn-work:/work vn-encoder`
  (или без Docker: Node 24 + ffmpeg, `node encoder/src/encoder.js worker`). NVIDIA: `ENC_HW=nvenc` с родным ffmpeg.
* **GitHub Actions (бесплатно):** секреты `MAIN_URL`, `ENCODER_TOKEN` → workflow `encoder.yml` каждые 30 мин проверяет очередь.
* **Сразу с диска, без загрузки через сайт:** `node encoder/src/encoder.js ingest stream.mkv --title "…" --date 2025-01-31 --tags "irl,кс" --profile av1`.

Загрузка через панель идёт частями по 16 МБ с докачкой → сырой файл во временную папку Blomp → задача в очередь →
кодировщик забирает, кодирует, заливает сегменты **прямо во время кодирования**, затем сырьё удаляется.

### 7. Первый вход
Открой сайт → «Войти через Telegram» → бот пришлёт кнопку подтверждения. Твой ID из `ADMIN_TG_IDS` = админ,
в меню появится «Панель».

Локально всё сразу: `cp env/main.env.example env/main.env; cp env/bot.env.example env/bot.env` (заполни) → `docker compose up --build` → http://localhost:8080

## Как работает рой (без единого Cloudflare-воркера)

* **Выбор ноды.** При старте просмотра main выдаёт подписанный токен и 3 кандидата: регион по часовому поясу
  зрителя, затем bounded-load rendezvous hashing (одно видео тяготеет к одним нодам → кэш горячий), с ограничением
  нагрузки — перегруженные ноды пропускаются. Браузер пингует кандидатов параллельно, берёт самую быструю и
  запоминает лучший регион. При ошибках плеер мгновенно переключается на следующую ноду; если весь рой недоступен —
  отдаёт сам main (настройка `mainFallback`).
* **«Почти сон» без 20–30 с пробуждения.** Render Free усыпляет сервис после 15 мин без входящих запросов и будит ~30 с.
  Поэтому main держит **тёплый пул**: минимум `warmMin` нод (по умолчанию 2) + столько, сколько нужно под текущих
  зрителей (`scaleAt` — порог нагрузки для расширения). Тёплые ноды пингуются каждые 9 мин. Лишние ноды переходят в
  режим `sleep`: кэш сброшен, heartbeat раз в 2 мин, CPU ≈ 0. Перед тем как их понадобится отдать зрителям, main будит
  их заранее, а пользователю сначала выдаются уже тёплые. Флаг `keepAllWarm` держит тёплыми все ноды.
* **Лимиты Render Free:** 750 инстанс-часов в месяц на аккаунт (хватает на 1 сервис 24/7) и ~100 ГБ исходящего
  трафика. Поэтому одна edge-нода на аккаунт. Счётчик трафика за месяц ведётся по каждой ноде; при `budgetGB`
  (по умолчанию 90) нода уходит в `budget` (drain) до следующего месяца. 30 нод ≈ 2,7 ТБ/мес отдачи.
* **Оптимизации edge:** LRU-кэш в RAM (`edgeCacheMB`), один запрос к Blomp на сегмент при любом числе зрителей
  (single-flight), предзагрузка следующих 1–2 сегментов, Range, keep-alive к Blomp, ~40 МБ RAM в простое.

## Качество и место

HLS fMP4, сегменты 6 с, одна общая AAC-дорожка, адаптивный битрейт. Профили (переключаются в панели/при загрузке):

| Профиль | Лестница | ≈ место на 1 ч |
|---|---|---|
| `av1` (по умолч.) | AV1 1080/720/480 + H.264 480 для старых устройств | ~1,6–2 ГБ |
| `av1compat` | AV1 1080/720/480 + H.264 720/360 | ~2,5 ГБ |
| `h264` | H.264 1080/720/480/360 | ~3,5–4 ГБ |
| `lite` | AV1 720/480 + H.264 360 | ~0,9 ГБ |

AV1 даёт ту же картинку при битрейте ~в 2 раза ниже H.264 → меньше места в Blomp и меньше трафика нод.
Плеер сам проверяет, тянет ли устройство AV1 аппаратно (`mediaCapabilities`), иначе берёт H.264.

## Сайт и плеер
* Главная: счётчики, тепловой календарь стримов за 12 мес, теги, фильтры по датам/длительности/сортировке, поиск
  (полнотекстовый, `#тег`, даты), бесконечная лента, «продолжить просмотр». Комментариев нет — специально.
* Плеер: своя MSE-реализация HLS; качество (авто/вручную), громкость (колёсико), скорость, главы, превью-раскадровка
  на таймлайне, статистика, PiP, театр, полный экран, двойной тап ±10 с, сохранение позиции, ссылка с таймкодом.
* Горячие клавиши (работают и в русской раскладке): `Пробел/K` пауза · `J/L` ±10 с · `←/→` ±5 с · `↑/↓` громкость ·
  `M` звук · `F` полный экран · `T` театр · `<`/`>` скорость · `0–9` переход к 0–90 % · `PgUp/PgDn` главы · `Home/End`.
* Профиль: аватар (обрезка в браузере → WebP) или импорт из Telegram, смена ника, уведомления о новых стримах,
  активные сессии, история и избранное.

## Админ-панель (`/admin`)
Обзор (зрители, нагрузка, очередь) · Видео (название, обложка, описание, теги, дата, видимость, удаление с очисткой
Blomp, анонс в бота) · Загрузка (докачка) · Пользователи (бан/разбан, роль, сброс ника/аватара, кик со всех сессий,
сообщение через бота, удаление, рассылка) · Серверы·рой (состояние, зрители, CPU, RAM, трафик за месяц, выкл/вкл,
drain, сон/пробуждение, сброс кэша, рестарт, пинг, диагностика, настройки тёплого пула и бюджетов) · Кодировщик
(очередь, прогресс, повтор/отмена) · Настройки (название, описание, техработы, регистрация) · Журнал действий · Бэкап.

## Ограничения первой версии
* main — единая точка для сайта/API: если он перезапускается (~30–60 с), уже начатые просмотры продолжаются с нод
  (токен живёт несколько часов), но новые не стартуют.
* При внезапном падении main могут потеряться изменения за последние `BACKUP_EVERY_SEC` секунд (по умолч. 2 мин).
* Регион ноды задаётся вручную (`EDGE_REGION`); у Render Free нет Азии/СНГ, ближайшие — Франкфурт и Сингапур.
* `images/` собраны под linux/amd64 (Render — amd64). Для arm-ПК пересобери: `./scripts/build-images.sh`.
